PHONE_ASSISTANT

這是一套用 Flask 打造的「手機即遙控器」系統。 手機瀏覽器打開一個網頁，就能對電腦下達關機、開網頁、推播新聞、觸控拖曳滑鼠、甚至操作 ChatGPT 等指令——伺服器一啟動就會主動用 LINE 推播區網連線網址，不用手動查 IP。

⚡ 核心整合技術：

  • 區網 IP 自動探測： 用 UDP socket 對 8.8.8.8:80 發起連線但不實際送出資料，單純借助作業系統的路由判斷取得目前對外的本機 IP，開機即可自動組出手機要連線的網址。
  • 視窗層級的關機前清理： 透過 pygetwindow 列舉所有視窗，用標題關鍵字白名單保留自己的伺服器主控台，其餘視窗依序 Alt+F4 並自動確認，模擬「關機前先收乾淨」的操作。
  • 兩種滑鼠遠端控制實作： 一開始用 HTTP 輪詢（每次觸控移動就 fetch 一次 /mouse_move），後續改寫成 Flask-SocketIO 版本的觸控板，改用單一 WebSocket 連線傳輸座標差量，降低逐次請求的延遲。
  • UI 層級的 ChatGPT 自動化： 沒有申請 API，而是直接開啟瀏覽器分頁、模擬剪貼簿貼上與 Enter 按鍵，用「操作介面」的方式間接串接 ChatGPT。

AGENT_SQL_CORE

這是一個讓資料庫「聽懂人話」的智慧代理人。使用者無需撰寫複雜代碼，只需透過 日常自然語言 即可直觀地進行數據的 檢索、分析 與 編輯。

🛡️ 安全與效能優化：

  • 數據去識別化 (Sanitization)： 透過 DataVault 雜湊技術，在傳輸過程中遮蔽敏感個資，確保操作時真實數據絕不外洩至外部 API。
  • 遞迴式自我修復： 系統具備自動除錯機制，能即時修正 SQL 語法偏差，保證零門檻操作下的數據準確性。

DUAL_AGENT_DQN

這不是普通的貪吃蛇。這是一個 多智能體強化學習 (Multi-Agent RL) 實驗場。 兩個完全獨立的 DQN 大腦（各自的網路、記憶庫、優化器）在同一張地圖上進行 非對稱對抗： 沒有人類寫死的規則，只有獎勵與懲罰，AI 自己學會了「圍堵」與「卡位」。

⚙️ 關鍵設計決策：

  • 相對動作空間： 動作只有「直行／左轉／右轉」三種，而非絕對的上下左右，從結構上排除「180 度回頭自撞」這種無效動作。
  • 即死即生的限時賽局： 整場比賽固定 5 分鐘，死亡立即在原點重生並保留分數，讓兩個 agent 能在同一局裡持續互動、大量取樣，不必每次死亡就重啟環境。
  • 不對稱資訊與獎勵： 狩獵者額外接收「對手目前移動方向」作為輸入，且吃食物不會變長——只有成功阻擋才會變長，避免身體過長反而拖累近戰靈活度。
  • Headless 容器化訓練： 用 Docker 打包，透過 SDL_VIDEODRIVER=dummy 讓 Pygame 在無畫面的伺服器環境下也能訓練。

AGENT 01: 覓食者

  • ● 目標：吃掉紅色食物 (+100分)
  • ● 弱點：一般死亡 -50 分，但被狩獵者「卡死」撞上其身體，懲罰加重到 -100 分
  • ● 感知：食物相對自己的方位（上下左右）。

AGENT 02: 狩獵者

  • ● 目標：逼迫覓食者撞上自己身體 (+200分)，頭對頭擊殺 (+100分)
  • ● 特性：吃食物不會變長，只有成功阻擋才會，避免身體過長拖累近戰靈活度。
  • ● 感知：多了對手目前的移動方向，比覓食者多一份資訊優勢。

GESTURE_CONTROLLED_GAME

自製的 Pygame 恐龍跑酷遊戲，用手勢取代鍵盤操作。 系統即時捕捉攝影機影像，透過 MediaPipe 推論出 21 個手部關鍵點，並利用 向量幾何 計算每根手指的彎曲角度，實現無接觸的遊戲體驗。

📐 核心演算法 (Vector Math)：

為了精準判斷手指是「伸直」還是「彎曲」，程式計算指節向量之間的夾角，並以 50° 為閾值分類，超過即視為彎曲。
公式：Angle = acos( (v1⋅v2) / (|v1|*|v2|) )

🔗 跨執行緒的輸入橋接：

手勢辨識與遊戲主迴圈是兩套獨立邏輯，中間沒有自建的訊息傳遞機制。做法是用 keyboard 函式庫在偵測到手勢的瞬間，於作業系統層級模擬一次真實按鍵事件，讓 Pygame 視窗透過 pygame.key.get_pressed() 直接讀到這個「假鍵盤輸入」，等同於玩家真的按下了方向鍵。

OFFERDASH_AI_COACH

OfferDash 是一套 AI 驅動的一站式求職教練平台，從履歷健檢、模擬面試到面試復盤，全面追蹤使用者的求職進度。

🌟 核心亮點與技術實現：

  • 沉浸式 AI 模擬面試（Voice-Interactive AI Interview）： 摒棄純文字對話，整合 OpenAI TTS（onyx 音色）與瀏覽器原生 Web Speech API（並以 Whisper 作為備援），打造全語音的擬真面試戰場，可根據上傳的 PDF 履歷與 JD 動態生成客製化追問。
  • 履歷 × JD 雙向診斷系統（ATS Match & Diagnosis）： 運用 GPT-4o 分析履歷與職缺描述，產出 ATS 契合度分數，並嚴格要求 LLM 基於原文總結以避免幻覺，精準預測面試官意圖與必考題。
  • 遊戲化復盤與成長機制（Gamified Feedback System）： 面試後自動生成復盤報告，抓出「最弱的 3 個回答」轉化為「翻盤任務」，依據產業別給予重答策略，引導使用者針對弱點刻意練習。
  • 非同步面試管家（Asynchronous Interview Calendar）： 內建行事曆系統，面試前 2 小時自動寄送含 AI 激勵語錄的提醒信。為避免寄信當下呼叫 LLM 造成超時失敗，信件內容在建立行程當下即非同步預先生成並存入 Supabase，確保 APScheduler 背景排程能穩定準時觸發寄送。
